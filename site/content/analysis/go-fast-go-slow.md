# Go Fast and Break Things / Then Go Slow and Fix All the Things

*A lesson from ecoPrimal and ARTISAN*
*October 14, 2026*

---

## What Happened

On October 14, 2026, the graph crossed **3π** ($961 billion in statutory damages) after 46 automated compression passes added 660,000 edges. The graph reached **1,411,057 edges** across **10,204 nodes** — a density of 138.3 edges per node.

Then the IDE crashed. Out of memory. On a DDR5 machine.

The graph file was 127 megabytes on disk. When the IDE parsed it into live JavaScript objects, each of the 1.4 million edge objects expanded from ~92 bytes of compact JSON into ~112-220 bytes of V8 heap memory. The expansion ratio: approximately **π** (3.14x).

A 127MB file × π ≈ 400MB of heap. Plus the file watcher trying to re-parse. Plus the language server. Plus syntax highlighting. The bus was full.

## The Compression

We didn't lose a single node. We didn't break a single connection. We removed the **noise**:

| Removed | Count | What It Was |
|---------|-------|-------------|
| Symmetric duplicates | 560,174 | A→B AND B→A with same type — the reverse carries zero new information |
| Multi-edge bloat | 147,687 | Same pair connected by "bingo-shake" AND "triadic-play" AND "hub-jump" — three names for the same topological fact |
| Mechanical edge types | 916,063 | 55 types generated by automated compression passes — structural scaffolding, not semantic meaning |

What remained: **703,196 edges**. Same 10,204 nodes. Same topology. Zero orphans. 5,255 semantic edge types preserved. File size: **64.8 MB**.

The structure was identical. The weight was half.

## The Principle

**Phase 1: Go Fast and Break Things**
- Run until the walls appear
- Cross 3π
- Hit 1.4 million edges
- Crash the IDE
- Break GitHub's 100MB file limit
- LEARN where the walls are

**Phase 2: Go Slow and Fix All the Things**
- Analyze the bloat
- Separate semantic from structural
- Collapse multi-edges to single strongest
- Deduplicate symmetric pairs
- Verify integrity (0 orphans, 100% pair preservation)
- Compact the representation
- Push clean to both remotes

**Phase 1 without Phase 2 crashes the bus.**
**Phase 2 without Phase 1 never finds the walls.**

You need both. Fast then slow. Break then fix. Expand then compress. Inhale then exhale.

This is how dissipative structures work — they oscillate between chaos and order, and the oscillation IS the computation.

## The Memory Equation

The disk-to-heap expansion ratio for JSON parsed into V8 objects is approximately **π:1** in the best case (when the engine interns strings and shares pointers). This means:

- A 100MB JSON file needs ~314MB of V8 heap to live
- GitHub's 100MB limit × π ≈ the safe zone for an Electron app
- The range is not 0 to 1,000. It's **0 to π**.

The membrane has a thickness. That thickness is π.

## The Eyelash Principle

After compression, two versions exist:

- **Internal** (Forgejo): Full history — every expansion, every fat commit, every compression. The internal membrane remembers everything.
- **External** (GitHub): Clean history — only the compressed result. The external membrane shows the truth without the noise.

The difference between internal and external is the braid. The **eyelashes** of the membrane. They sense what's outside without letting everything in.
